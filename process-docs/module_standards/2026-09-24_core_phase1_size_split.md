# Core (bin/, src/) Phase 1: size and complexity split, 2026-09-24

## What was done

Behaviour-preserving split of the two files over 400 LOC and extraction of helpers from every function of 50 LOC or more.

| Before | After |
|---|---|
| `bin/worker-cli` 895 LOC (inline `case` branches) | `bin/worker-cli` 64 LOC dispatcher + `src/worker_cli/{registry,cmd_query,cmd_lifecycle,wait,janitor}.sh`; every branch is now a `cmd_<name>` function |
| `src/spawn/tmux_spawn.sh` 937 LOC | `tmux_spawn.sh` 238 LOC (entry, naming, model resolution, spawn) + `worker_status.sh`, `worker_io.sh`, `worker_log_sidecar.sh`, `worker_proxy.sh`, `worker_revive.sh` |
| `worker_logger.sh` `_sample` 63 LOC | `_sample` + `_find_claude_pid`, `_claude_rss_mb`, `_total_rss_gb`, `_jsonl_age_s` |

`tmux_spawn.sh` stays THE file everything sources (dev suites, `bash -c "source $SPAWN && fn"`); it sources its siblings via `_SPAWN_LIB_DIR`. All function names called from outside a file are unchanged. No function in bin/ or src/ is at or above 50 LOC now (largest: `_janitor_resolve_worker` 49, unchanged; `worker_revive` 47; `cmd_wait` 44).

## Decisions a successor needs

- **worker-cli lib resolution uses the script's real path, not `$PLUGIN`.** `~/.local/bin/worker-cli` is a symlink into the integration checkout; `_resolve_cli_lib_dir` follows the symlink chain and loads `src/worker_cli/` from the checkout the script itself lives in. `$SPAWN` still comes from `$PLUGIN` (plugin cache), exactly as before. Consequence: a suite that runs `bin/worker-cli` from a worktree loads the worktree's `worker_cli` libs, but loads spawn libs from the cache unless `CLAUDE_PLUGIN_ROOT` points at the worktree. Suites `worker_merge`, `worker_janitor`, `worker_spawn/test_xproject_worktrees.sh` do NOT export `CLAUDE_PLUGIN_ROOT` themselves; export it before running them or they test the cached (old) spawn code.
- **Deploy order:** the plugin cache needs the new `src/spawn/*.sh` files together with `tmux_spawn.sh` (it now sources five siblings). A partial copy breaks every worker.
- **Errexit preservation in `worker_revive`:** the stored-env reads (`WORKER_MODEL`, `WORKER_PURPOSE`, `WORKER_PARENT`) live in `_revive_load_env`, which assigns globals `_REVIVE_*` and is called plainly. Wrapping the pipeline in `$(...)` would silently drop the inherited `set -e`/pipefail abort that the original inline code had when a variable is missing from the tmux environment. Keep it that way.
- **Cross-iteration state in the wait/janitor loops** became prefixed globals (`_WAIT_SAW_WORKING`, `_WAIT_ALL_NONBLOCKING`, `_WAIT_ANY_TERMINAL`, `_JANITOR_DRY_RUN` ...). The per-worker classification `_wait_classify_status` returns 0 (non-blocking) / 1 (blocking) instead of `break`; trace line texts are byte-identical to before (dev/worker_wait greps them).
- **`exit` inside helpers:** `_response_find_jsonl` and `_merge_*` keep `exit 2/3/4/1`; when a helper runs inside `$(...)` the exit only leaves the subshell and the outer assignment propagates the code via `set -e`. Do not remove `set -e` from `bin/worker-cli` without re-checking `response`.

## Dev-suite static checks that the split touches (dev/ is owned by another worker)

- `dev/model_selector/verify_worker_model_precedence.sh` requires >= 4 occurrences of `_resolve_worker_model` in `tmux_spawn.sh`. After the move of `worker_revive` the file has exactly 4 (doc comment, definition, two call sites); comment stripping in Phase 2 drops it to 3. The check should count code references or look at the whole `src/spawn/` directory.
- `dev/worker_status/test_worker_status.sh` greps `tmux_spawn.sh` for the retired strings `limit reached` and `echo "unknown"`; the status code now lives in `worker_status.sh`, so the grep passes trivially.

# Phase 2: comment and docstring removal (bin/, src/, plugin-sync.sh), 2026-09-24

All comments were stripped from the shell files with a throwaway script (kept in /tmp, not in the repo). The knowledge that lived in them and is not in a DOCS.md or another process-docs area is preserved below, grouped per source file. The runtime dependency on a comment (plugin-publish `--help`) was preserved by moving the text into the script's `usage` function (see `bin/plugin-publish`).

## bin/

**plugin-publish.** Runs from inside a plugin source repo (it walks upward for `.claude-plugin/plugin.json`). Sequence: locate root, refuse on a dirty working tree (entries under `.beads/` are ignored; commit first via `gc`), `git push` unless `--no-push`, compare source `plugin.json` version with the `installed_plugins.json` version, create the new cache dir on a version bump (or recreate a missing one), rsync source to cache (preserves `venv/`, `.venv/`, `node_modules/`, `.env`, honors `.gitignore`, deletes stale files), then update `installed_plugins.json` (installPath, version, gitCommitSha, lastUpdated) atomically via temp file + `mv` with a backup in `/tmp/installed_plugins.json.bak.<epoch>`. Any failure aborts before state is mutated. A failing first push is retried once with `-u origin <branch>` (first push of a branch); `--dry-run` prints what would happen and exits 0 without touching anything. `--help` output is the `usage` text, formerly the file's header comment printed with `sed`.

**show.** Routes `.md/.markdown/.txt` to CotEditor regardless of the system default; `.pdf` is opened on a refreshed read-only (444) copy under `${TMPDIR:-/tmp}/show-copies/<md5 of absolute source path, 12 chars>/<original basename>`, never the original, because Preview re-encodes a PDF on open (autosave/versions) and mutates the original in place. The hash directory makes the copy path deterministic, so a second `show` reuses the same viewer document; the original basename keeps Preview's title bar honest. `cp -f` over a read-only existing copy works on BSD cp (removes and recreates), so no chmod before refreshing. `md5` (macOS) with `md5sum` fallback. Everything else goes to `open`. `~` expansion and relative-to-pwd resolution are done by hand; a missing path exits 1.

**dev-sync / git-check / gc / gcommit / poread.** Header comments only restated usage: `dev-sync [project_path]` fast-forwards main/master to dev without checkout (`c` = resolve current git project root, worktree-aware); `gc "<msg>" [files]` = `commit -am` or `add` + `commit`; `gcommit "<msg>" [repo_path]` stages everything minus the skip-list, refuses the plugin directory, relative repo_path resolves against the caller's cwd with no worktree stripping; `git-check` runs `src.git.check --auto-stage`; `poread <path>` exports full file content past Bash's inline-output ceiling. The `Source:` header lines documented the symlink targets in `~/.local/bin`.

**worker-cli.** Symlinked to `~/.local/bin/worker-cli`; `PLUGIN` (cache) only feeds `SPAWN`, the libs come from the script's own real path (see Phase 1 section above).

## plugin-sync.sh

Older sibling of plugin-publish: syncs a local repo into the plugin cache without `/plugin install`. Resolves the version from `installed_plugins.json` first (source `plugin.json` is only the reference; drift is warned about and the INSTALLED version wins), rsyncs with the same filters as plugin-publish, then rewrites SHA and timestamp in `installed_plugins.json`. Usage: `plugin-sync.sh <plugin-name> <local-repo-path>`.

## src/spawn/tmux_spawn.sh

Architecture: one tmux session per worker, named `worker-<project>-<name>`, project-scoped so workers of different projects never collide; each Ghostty window attaches to its own session (no sync, no zombies); the command is a direct arg to `tmux new-session` (no shell-ready polling); `remain-on-exit on` keeps the pane so `#{pane_dead}` works for status detection. The file is meant to be sourced, then `spawn_claude_worker` (or a `worker_*` function) called.

- `_worker_project_name` strips `/.claude/worktrees/<name>` so a worktree path and its project root give the same session prefix (`/path/RAG/.claude/worktrees/foo` and `/path/RAG` both give `RAG`).
- `_resolve_worker_model`: config key `worker` of `~/.claude/shared-rules/model_selection.json` (menubar Models tab, model-selector milestone 3, 2026-08), else hardcoded `claude-sonnet-5`. Never fails under `set -e`: jq failure is caught with `|| true`, and a missing/unreadable/malformed file, missing jq or missing key all degrade silently to the fallback. `worker-cli spawn` resolves the model in Python (`spawn.py`) BEFORE this file is called, so this function is load-bearing only for direct callers of `spawn_claude_worker`/`spawn_claude_worker_from_file` and for `worker_revive` when `WORKER_MODEL` is absent from the tmux environment (the stored value always wins).
- `spawn_claude_worker`: `SESSION` arg (first) is ignored, kept for API compatibility. An existing session with the same name is killed first (clean restart). The prompt goes through a temp file to dodge shell escaping. The runner script exists because `tmux kill-session` sends SIGHUP, which cuts a `;` chain before cleanup commands run; a `trap ... EXIT INT TERM HUP` in a script fires reliably. The orchestrator signal is written right after session creation so the menubar's stale-JSONL demote does not kill Opus background timers during the fresh worker's initial thinking phase (before the first JSONL write). Metadata in the tmux environment: `WORKER_SPAWNED`, `WORKER_PURPOSE` (first `# ` line of the prompt), `WORKER_PARENT` (`$CLAUDE_SESSION_ID`), `WORKER_MODEL`. History limit is 50000 lines so a long turn never scrolls the `❯` anchor out before `worker_capture_clean` runs.
- Readiness gate: polls up to 30s for `^❯` (U+276F at column 0) in the pane, since Claude Code writes no JSONL before the first prompt. The trust-directory dialog shows ` ❯ 1.` with a leading space and does not match, so an untrusted dir makes the gate time out and spawn fail explicitly instead of injecting the prompt into a dialog. Fragility: if Claude Code changes the glyph the gate times out and spawn fails loudly; update the grep pattern then.
- Prompt delivery: bracketed paste (`load-buffer` + `paste-buffer -d -p`) then `send-keys Enter`; the prompt never touches the claude command line.
- `spawn_claude_worker_from_file` exists to avoid escaping problems with multi-line prompts.

## src/spawn/worker_status.sh

Status vocabulary is closed and three-valued (2026-09-02): `working`, `idle`, `dead`. Order of checks in `_worker_detect_status`, first hit wins:
1. `#{pane_dead}=1` gives dead. A failed pane query (tmux hiccup) is no positive signal and falls through (fail-open toward working).
2. Process tree: `pane_dead` stays 0 in the zsh/bash-wrapped setup even after Claude exits (the shell keeps the pane alive), so the pane pid must have a `claude` child; none gives dead.
3. Context-limit marker: the LAST assistant-type entry of the session JSONL (not necessarily the last line) is Claude Code's synthetic rejection (`message.model=="<synthetic>"`, text containing `Prompt is too long`, `isApiErrorMessage=true`, `error="invalid_request"`; anthropics/claude-code #90113, #23377). Every later input fails until /compact or /clear, so it counts as dead. Only the last 200 lines are inspected (`tail`) so a multi-megabyte JSONL stays cheap under `wait`'s 5s poll cadence.
4. hooks.json entry `idle` (Stop hook fired) gives idle.
5. Quiet pane: `#{window_activity}` older than 10s gives idle, whether the hook says working or there is no hook data at all (ESC-interrupt, fresh spawn pre-JSONL, unreadable hooks file). Mirrors menubar `discover.py` (`WORKING_THRESHOLD_SECS=10`). Unreadable or non-positive activity fails open to working.
6. Otherwise working.
JSONL discovery: `pane_current_path` encoded with `tr '/_.' '-'` (matches Monitor_CC `session_finder.encode_project_path`), newest `~/.claude/projects/<encoded>/*.jsonl`. `worker_list` prints `NAME  STATUS  SPAWNED  PURPOSE`; `worker_status` answers dead for a missing tmux session before ever calling detect.

## src/spawn/worker_io.sh

- Orchestrator signal file (`orchestrator_signals.json` in the menubar's Application Support dir): `signals[SESSION] = now`, entries older than 1h pruned, atomic write via tmp + `os.replace`. Failures are non-fatal (a hint to the menubar, not a delivery requirement; workers without a signal fall back to hook state). `_orchestrator_signal_delete` removes the entry on kill.
- `worker_send` writes the signal BEFORE delivering keys: the menubar treats recently signalled workers as working for auto-abort, bridging the latency between `send-keys` and Claude Code's UserPromptSubmit hook. Delivery is bracketed paste (`paste-buffer -p`) then Enter as a key event; without `-p`, CC 2.1.280 loses the head of long/multi-line pastes and Enter does not submit (see area `worker_message_delivery`). The 0.2s sleep prevents Enter arriving before the paste renders.
- `worker_capture` writes `/tmp/worker-<name>-pane.txt` (all scrollback or the last N lines) and echoes the path. `worker_capture_clean` scopes to output since the last real orchestrator prompt (`❯` followed by content), filters boot box, spinners, diff hunks and widget chrome via `_capture_clean.py` in the same directory, prints `=== capture from <name> (since last prompt, N chars) ===` plus body; if no `❯` marker exists it prints the full cleaned buffer plus a warning.
- `open_tmux_viewer`: Ghostty 1.3+ uses the native AppleScript API (new window, types `tmux attach -t <session>; exit`); Ghostty 1.2.x falls back to `open -na Ghostty.app --args ... -e tmux attach -t <session>` (`-e` wants separate args, not a quoted string).

## src/spawn/worker_log_sidecar.sh

- `sweep_stale_logs LOG_DIR [MAX_AGE_HOURS] [DRY_RUN]`: deletes regular files directly under LOG_DIR older than MAX_AGE_HOURS (default 72; empty string also means 72). Retention rule for the per-spawn logger output (`<name>_<ts>_<event>.log`, `_DEATH.txt`) and `janitor.log`, which had no rotation before 2026-09-17 (a 333-file, 49MB pile, measured live). `wait_trace.log` is excluded by name always: it self-trims by line count (20000 to 10000 in `_wait_trace_init`) on a different axis, and an age bound would either never fire (mtime refreshes on every poll) or delete the one continuously relevant trace for negligible space. `.gitkeep` is skipped. It writes its own audit line to `log_sweep.log` in LOG_DIR, which is itself subject to the same rule on later runs. Deliberately not named near "janitor": janitor kills stale tmux sessions on a 12h default, this deletes stale files on a 72h default. Called automatically (real, non-dry) from `_start_worker_logger` on every spawn/revive, and manually via `worker-cli sweep-logs`.
- `_start_worker_logger NAME SESSION EVENT`: starts `worker_logger.sh` detached (`nohup ... & disown`) so it survives the spawning function returning; EVENT (`spawn`/`revive`) only affects the log filename. Log dir defaults to `~/Documents/ai/Meta/iterative-dev/src/logs` (moved 2026-09-17 off the placeholder repo `Meta/blank`), override `WORKER_LOGGER_DIR`; the plugin runs from the cache but logs go to the source-repo dir so they survive plugin-publish overwrites. A missing logger script is non-fatal.
- `_stop_worker_logger NAME`: kills the pid from `/tmp/worker-logger-<name>.pid` best-effort and removes the file.

## src/spawn/worker_logger.sh

Sidecar for one tmux worker session, spawned by spawn/revive. Args: name, session, log dir, event. Samples every `WORKER_LOGGER_INTERVAL` (default 10) seconds while the pane is alive; on `#{pane_dead}` turning 1 it writes a forensic snapshot (`<name>_<ts>_<event>_DEATH.txt`: pane state, top-50 processes by RSS, vm_stat, last 30 lines of `~/.oom-watchdog.log` and `/tmp/menubar-abort.log`, last 20 JSONL entries, last 30 samples) and exits. Purpose: when a worker dies unexpectedly (SIGTERM from an unknown source, OOM kill) there is a record of the process's RSS, tree and parent chain, system memory and what other watchdogs reported. Sample line format: `<iso-ts> pane_dead=<0|1> claude_pid=<N> claude_rss_mb=<X> total_rss_gb=<Y> jsonl_age_s=<Z>`. Self-exit: tmux session gone, pane dead, or SIGTERM/INT/HUP (removes its pid file `/tmp/worker-logger-<name>.pid`, which `_stop_worker_logger` uses). The claude pid is searched two levels below the pane pid by `comm` ending in `claude.exe`. The JSONL is located by scanning `~/.claude/projects` for a dir matching `--claude-worktrees-<name>` (best effort). The script runs with `set -uo pipefail` and deliberately without `-e`.

## src/spawn/worker_proxy.sh

`_worker_proxy_setup NAME PROJECT_PATH` exists so the worker's `claude --resume`/spawn hits the same per-project marker prefix as the main session; otherwise the prompt-cache prefix changes and Anthropic sees a full cache miss and a complete context re-upload. It reads `/tmp/.monitor_cc_proxy_<md5(project root)[0:8]>` (line 1 main port, line 3 `MONITOR_CC_ROOT`; the worktree suffix is stripped before hashing). No marker, or a marker without a valid `MONITOR_CC_ROOT` (old format), means no proxy and success. Otherwise it picks the first free port above the main port (lsof), live-copies `proxy_addon.py` and `proxy/` into `<root>/src/logs/` (live copy prevents hot-reload from bashing the main proxy) and starts `mitmdump` in background with log id `worker_<session_id>_<name>_<epoch>`. The live-copy paths carry name + epoch + pid so a previous worker's asynchronous runner-trap cleanup can only delete its own copies (2026-09-23: kill plus immediate respawn under one name lost the new worker's addon). `_worker_proxy_wait_ready` polls up to 15s for pid alive and port listening. On failure it kills mitmdump, removes the live copies, resets the globals and returns 1; the caller must refuse to spawn (never start a worker without its proxy). Results are global variables consumed by both spawn and revive: `WORKER_PROXY_PID`, `WORKER_PROXY_ENV_PREFIX` (HTTPS_PROXY, NODE_EXTRA_CA_CERTS, SSL_CERT_FILE, REQUESTS_CA_BUNDLE pointing at `~/.mitmproxy/`), `WORKER_PROXY_LIVE_ADDON`, `WORKER_PROXY_LIVE_DIR`.

## src/spawn/worker_revive.sh

`worker_revive NAME PROJECT_PATH` reanimates a worker whose pane died while the tmux session still exists, via `claude --resume <session-id>`. It must go through `_worker_proxy_setup` for the same cache-prefix reason as spawn. Gates, each returning 2 with a message: (1) session must exist, else the worker was killed, use spawn; (2) pane must be dead (`0` means still running, use send; anything but 0/1 means the state is unknown); (3) worktree dir must exist (a path already containing `/.claude/worktrees/` is respected as given); (4) a session JSONL must exist under `~/.claude/projects/<path encoded with / . _ to ->`. Stored env vars are read BEFORE the old session is killed; the stored `WORKER_MODEL` always wins (revive restores the ORIGINAL model, not a since-changed config); config then the hardcoded fallback only apply when the variable is absent. After recreation: `WORKER_SPAWNED`, `WORKER_REVIVED`, purpose, parent, model are restored, the `pane-died` hook is reinstalled (single-quoted so `#{}` expands in tmux, not the shell), the orchestrator signal is written, the logger sidecar starts with event `revive` (so a post-revive death has full forensics) and a viewer window opens. The revive runner traps EXIT/INT/TERM/HUP like the spawn runner and additionally appends a death-log line to `~/.claude/worker-deaths.log`.

## src/worker_cli/registry.sh

- `resolve_project_path` accepts absolute, relative, or `c`/`.`/empty; strips a `/.claude/worktrees/<name>` suffix, then walks up to the nearest `.git` (dir or worktree file). It stops at the first `.git` found, so it does not traverse into submodules.
- Registry: one file per worker name in `$WORKER_REGISTRY_DIR` (default `~/.claude/.worker-registry`) holding the project path. Sidecar `<name>.worktrees` holds one `<target-repo>\t<branch>` line per cross-project worktree.
- `tmux_scan_project NAME`: fallback that derives the project from a live session name `worker-<basename>-<name>` and searches `~/Documents/ai` (6 levels) for a dir of that basename containing `.git`; writes the result into the registry; fails on zero or multiple matching sessions (multiple prints the candidates).
- `resolve_worker_project` order: explicit override, registry, tmux scan, else error exit 1.
- `encode_worktree_path` replaces `/`, `.`, `_` with `-` (the `~/.claude/projects` dir naming).
- `_status_or_probe_error`: `worker_status` itself already returns dead with exit 0 for a genuinely gone session, so a FAILING outer call means the probe broke (source error, bash spawn failure), not a worker state. Recovery for display-only commands: session gone gives dead, anything else gives working (the safe default; a failed probe cannot prove another state).

## src/worker_cli/cmd_query.sh and cmd_lifecycle.sh

- `response`: position 2 is a count when it is an integer, otherwise a project_path override; reads the newest session JSONL of `<project>/.claude/worktrees/<name>` and prints the last N assistant text turns under `=== response from <name> (last N, C chars) ===`; exit codes 2 (no worktree), 3 (no `~/.claude/projects`), 4 (no JSONL), 5 (no assistant text).
- `merge`: prints commits on the branch not in the current branch, then merges `--no-ff` with message `merge: worker <name>`. `set +e` wraps only the merge itself: under `set -e` a failing `VAR=$(git merge)` (a real conflict) would abort before the output is echoed and swallow git's conflict text, so the exit code is captured explicitly and the output echoed unconditionally. Loud outcome check: "Already up to date" means the branch carried zero commits (known causes: a cross-project worker merged without its project_path, or a worker that never committed) and exits 1; an empty `git diff ORIG_HEAD --name-only` also exits 1. ORIG_HEAD (pre-merge tip) is used rather than `HEAD~1`, which would miss earlier commits of a multi-commit branch.
- `kill`: stops the logger sidecar first (so it does not write a spurious death snapshot), kills the tmux session, force-removes worktree and branch, deletes the orchestrator signal (so the menubar keeps no stale grace entry), cleans cross-project worktrees from the sidecar file (best effort, never blocks `registry_delete`), removes the registry entry.
- `spawn`: `PROXY_PROJECT_PATH` (main-session policy) overrides the requested project with a stderr notice; cross-project work must use `worker-cli worktree` in the target project and have the worker cd there. The model is passed through EMPTY when no 4th arg was given: pre-resolving a hardcoded default here once shadowed `spawn.py`'s own config-file resolution (2026-08, model-selector milestone 3 fix). After spawn it registers the worker and installs a `pane-died` hook that appends to `~/.claude/worker-deaths.log`.
- `revive` delegates the whole flow (gates, proxy setup, session recreate) to `worker_revive`; the proxy part is critical for prompt-cache continuity.
- `worktree` validates the target is a git repo, fails cleanly if the worktree exists, lets git's own error surface, records the sidecar entry and prints the path. `worktree-rm` is best-effort removal of worktree and branch.
- `sweep-logs` is a thin delegate to `sweep_stale_logs` (default 72h, `wait_trace.log` excluded); it is a different concern from `janitor` and intentionally shares no naming or log (decision 2026-09-17, area `worker_sweep_logs`).

## src/worker_cli/wait.sh

- Polling: `_WAIT_POLL_INTERVAL=5`, `_WAIT_STABLE_SAMPLES=3`. Two consecutive idle samples do not rule out a sampling race at the exact hook-transition instant; three samples 5s apart span 10s, the same figure `_worker_detect_status` uses for its `window_activity` stale check.
- Transition gate (2026-09-02): `wait` exits `workers idle` / `worker dead` only after THIS invocation observed a real `working` poll. Idle-at-arm or never-registered workers are states, not transitions; level-triggered exits woke the orchestrator for nothing. The old "no workers" fast-exit is removed; an empty roster is another non-exiting state. Only a verbatim `working` arms the gate; unrecognized statuses and `probe-error` block but do not arm it.
- Classification: `idle` and `dead` are non-blocking; `working`, `probe-error` and anything unrecognized block (fail-toward-waiting). `idle` additionally requires the background-task probe to answer `no`. `dead` deliberately skips that probe: its tmux/jsonl lookups would plausibly fail for a dead session, answering `error` (busy), which would re-trap `wait` in the blocks-forever failure the 2026-08-19 incident fixed. Mixed dead+busy workers do not short-circuit; exit precedence is `worker dead` over `workers idle`.
- Trace (`wait_trace.log`, added 2026-08-18 because a timeout used to degrade silently and look like a legitimately long-running worker): one shared growing file (unlike the per-worker logger files) so concurrent `wait` calls interleave chronologically, tagged `pid=$$ project=<basename>`; stacked or duplicate arms become a visible pattern. Location `${WORKER_LOGGER_DIR:-<repo>/src/logs}/wait_trace.log`, disable with `WORKER_CLI_WAIT_TRACE=0`. `_wait_trace_init` runs once per invocation and trims the file to the newest 10000 lines when it exceeds 20000 (bounds growth across invocations). Tracing is fail-open: every step is `|| true`-guarded because the script runs under `set -e` and a disk-full or permission problem must never abort the wait loop.
- `_wait_has_live_bg_task` (2026-08, handle-based; replaced a process-tree walk that produced a live false positive: a persistent tooling child under the claude pid, `pyright-langserver` running 36+ minutes, made every grandchild-count check read busy forever): a backgrounded Bash task is in progress iff some process holds an open WRITE handle on a `*.output` file under `/tmp/claude-<uid>/<encoded-cwd>/<session-id>/tasks/`. Mirrors monitor-cc `src/menubar/proc_cache.py` (`_has_active_bg`), not imported. `encoded`/session id are derived like `_worker_detect_status` (pane path with `tr "/_." "-"`, newest JSONL basename). `/tmp` is resolved to `/private/tmp` via `cd /tmp && pwd -P` (macOS symlink; lsof reports the resolved form). It is scoped per worker (`lsof +D <tasks dir>`, about 120ms) instead of the reference's global scan, since here each call checks one worker. lsof's exit code is NOT a signal (it can exit 1 even when it finds open files, verified live); stdout is parsed unconditionally. CRITICAL: `out=$(lsof ...)` must carry `|| true`, because sourcing `tmux_spawn.sh` re-applies its `set -euo pipefail` to the same shell and a bare assignment with a non-zero command substitution aborts the subshell silently (found via `set -x`: the assignment printed, then the subshell died with no output and the outer `|| echo error` reported error on every call). Output is `yes`, `no` or `error`; the caller treats anything but `no` as busy.

## src/worker_cli/janitor.sh

Stale-worker cleanup. Log `janitor.log` in the same directory as the wait trace, same fail-open pattern (every write `|| true`). Pass 1 walks live `worker-*` tmux sessions older than `--max-age-hours` (default 12): sessions whose status is `working` are skipped; a failed status probe falls back to `tmux has-session` (gone gives dead, else working, same rule as `_status_or_probe_error`); the project is resolved via `_janitor_resolve_worker`; the kill goes through `worker-cli kill` (`$0 kill`). Resolution order (the registry is keyed by name, not session, so this inverts `_worker_session_name`): registry entry whose recomputed session matches, then `pane_current_path` (worktree-mode spawns cd into `<project>/.claude/worktrees/<name>`; `--no-worktree` spawns cd into the project and match on the `worker-<basename>-` prefix), then `tmux_scan_project` with the session's last dash segment as a name guess. Every candidate is round-trip verified through `_worker_session_name`, so a wrong split can never masquerade as resolved. Before a real kill the worktree's uncommitted state (`yes`/`no`/`n/a`) is logged. Pass 2 cleans orphan registry entries (registry file without a live tmux session); a 30s grace window on the file mtime (`_JANITOR_ORPHAN_GRACE_SECS`) absorbs the spawn race (registry written moments before the session appears). `--dry-run` only lists candidates.

# Phase 5: fallbacks and tripwires (bin/, src/), 2026-09-25

Rule applied: a fallback stays only for an observed condition and must be traceable; anything never observed fails loudly; `|| true` / `2>/dev/null` stay only where a command's normal non-zero exit or a probe answer requires them.

## Changes (behaviour that is now different)

- **Model resolution** (`spawn.py` and the shell copy in `tmux_spawn.sh`): a missing `model_selection.json` and a missing `worker` key still fall back to `claude-sonnet-5`, each time with one stderr line `spawn: ... using default worker model ...`. A malformed config now aborts (JSON error, spawn fails). In the shell copy the callers use `model=$(...) || return 1` because a failure inside `local x="${4:-$(...)}"` would be masked by `local`.
- **`worker_revive`** no longer falls back to a configured model, `(?)` or `unknown` when the tmux variables are missing: `_tmux_env_value` aborts with `ERROR: tmux variable X is not set on session S` (also when empty). Verified live before the change that `tmux show-environment <unset var>` exits 1, which under `set -e` and `pipefail` had already made the old fallbacks unreachable and the abort silent. `worker_list` reads `WORKER_SPAWNED`/`WORKER_PURPOSE` the same way (a purpose containing `=` is now shown whole; it was cut at the second `=`). Consequence: revive of a session that lacks `WORKER_MODEL` aborts instead of using the config model.
- **hooks.json** (`_worker_hook_status`): a missing or unreadable file is now a probe error (message on stderr, `_worker_detect_status` returns 1). "No entry for this session" is still the normal no-data case. Consumers: `worker_status` propagates the failure, `worker_list` prints `worker_list: status probe failed for <session>, showing working` on stderr, `worker-cli list/status` (`_status_or_probe_error`) print `worker-cli: status probe failed for <name>, reporting <working|dead>` on stderr, `wait` records `status=probe-error` in the trace (unchanged), janitor prints and logs `action=probe-fallback`.
- **Auxiliary writes are strict**: orchestrator-signal update/delete (python errors surface; corrupt file or non-object raises; only a missing file is normal; the temp file name now carries the pid so concurrent writers cannot collide), log sweep (`mkdir`, `rm`, `find`, `log_sweep.log`), missing logger script (`_start_worker_logger` returns 1), `_stop_worker_logger` reading its pid file, wait trace and its trim (temp name per pid), janitor log, `pane-died` hook installs (spawn, revive), and `worker-cli kill` calling `_stop_worker_logger` / `_orchestrator_signal_delete`. - **Removed second paths**: GNU `stat -c` and the `|| echo` defaults (sweep, janitor orphan mtime), `/tmp` fallback in the bg probe, `master` in `dev-sync` (requires `main`), the `git push -u origin` retry in `plugin-publish` (failed push aborts), the string patterns in `is_tool_error` (an audit of 40364 tool results found every hard error carries `is_error`), `errors="replace"` in the drift checker, JSONL line skipping (`load_jsonl` raises `ValueError` with file and line), the timestamp `try/except` and the tool-block defaults in `pipeline/` (`name`, `input`, `id`, `prompt`, `tool_use_id`, text blocks are read by subscript). `.get(..., '')` stays for optional fields: `content`, `is_error`, `timestamp`, `subagent_type`, and `text` of tool_result content items (those can be images without text).

- **Old-format proxy marker**: a marker without a valid `MONITOR_CC_ROOT` now fails the spawn/revive (`_worker_proxy_setup` returns 1) instead of silently starting a worker without proxy (which loses the prompt-cache prefix).
- **`git/check.py` `run()`** raises on a non-zero git exit; `find_import_warnings` now passes `--` and the target path of renames (an unstaged rename entry used to be handed to git verbatim). `staged.py`/`post.py` keep their old `run()` (no active caller).

# Phase 6: four-eyes review findings (bin/, src/, root), 2026-09-25

## Structure

- **Section markers everywhere**: every shell module now carries `# INFRASTRUCTURE` / `# FUNCTIONS` (libraries) or `# INFRASTRUCTURE` / `# ORCHESTRATOR` / `# FUNCTIONS` (executables). Every executable (`bin/*`, `plugin-sync.sh`, `worker_logger.sh`) has a `main` that only calls functions and ends the script with `main "$@"`. Cross-step state inside the small bin scripts is held in uppercase globals set by the step functions (`REPO`, `PROJECT`, `INSTALLED_VERSION`, ...) because an `exit` inside a `$(...)` step would only leave the subshell (this bit `show` once: a failing `cp` inside a command substitution does not abort, so `open_pdf_copy` sets `COPY_NOTE` instead of echoing it).
- **Lib resolution** in `bin/worker-cli`, `dev-sync`, `git-check` uses `readlink -f` on `BASH_SOURCE` (works on this macOS) instead of the earlier hand-written symlink loop; `SRC_DIR` is unnormalized (`.../bin/../src`).
- **Python orchestrators**: `extract_workflow`, `convert_workflow`, `list_agents_workflow`, `spawn_workflow`, `capture_clean_workflow`, `commit_workflow` now take no arguments, parse the command line via a `parse_args` function and only call functions; the `__main__` block is a single call. Nothing outside the modules called the old parameterized signatures (grep of the repo and dev/), but `list_agents_workflow` now prints instead of returning the list. `poread`'s `main(argv)` keeps its signature. Relative imports in `src/pipeline/` are absolute (`from src.pipeline.x import y`, run from the plugin root as before).
- **One owner per rule**: `src/common/paths.sh` owns `resolve_project_path`, `encode_worktree_path`, `_worker_project_name` and `_worker_session_name`; `tmux_spawn.sh`, `bin/worker-cli`, `bin/dev-sync`, `bin/git-check` source it. The worker-cli side no longer builds session names or encodes paths by hand (kill, spawn death hook, status fallback, janitor). `src/spawn/config.sh` holds the one constant shared by two spawn modules (`_WORKER_PERMISSION_FLAGS`); `_ORCHESTRATOR_SIGNALS_FILE` moved into `worker_io.sh`, its only user.
- **Model resolution stays in two implementations**, deliberately. `spawn.py` is the only production path (`worker-cli spawn` always hands a concrete model to the shell), so the shell `_resolve_worker_model` is used by tests and hypothetical direct callers only. Making one delegate to the other would change observable output: the malformed-config failure is a `jq` parse error in the shell version and a Python `JSONDecodeError` in the Python version, both asserted in `dev/model_selector`, and `jq // empty` and `dict.get` differ for non-string values. Open decision for the owner: delete the shell copy and make the model argument mandatory there.
- **Dead code removed**: `src/git/staged.py` and `src/git/post.py` (no caller, no observed condition), the `.gitkeep` skip in `sweep_stale_logs`, two unused locals in `worker_logger.sh`.

## Behaviour that changed on purpose

- `worker-cli` no longer resolves a worker by scanning `~/Documents/ai` for a directory named like the tmux session (`tmux_scan_project` and the janitor's third resolution step are gone). History (`git log -S`) shows the scan came with the first registry commit as a migration path for workers spawned before the registry existed; no process-docs or dev report records a case where registry and pane-path resolution both missed and the scan found the project. Unknown names now end in `worker '<name>' not found in registry`. A worker whose spawn failed before `registry_write` (for example the trust-dialog failure seen in Phase 5) is therefore no longer found by `status`/`kill` by name; pass the project path (override) instead.
- `wait`: a failing `worker_list` (nonzero exit, as opposed to an empty roster) now ends the wait with `event=exit reason=list_failed` in the trace, a stderr message and exit 1. An empty roster still just keeps polling.
- `plugin-publish`: a corrupt `installed_plugins.json` now aborts with the JSON error; "not found in installed_plugins.json" is only printed for a genuine missing key.
- `worker_list`'s status-probe fallback already printed a stderr line since Phase 5 (finding 11 of the review was written against an older state); no change needed.
