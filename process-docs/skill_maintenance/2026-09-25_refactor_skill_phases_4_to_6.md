# Refactor skill: Phase 4 Steps 3-5, Phase 5 and the new Phase 6 (2026-09-24/25)

Orchestrator entry. Covers edits to `skills/iterative-dev-refactor/SKILL.md` made on the user's instruction in the chat, published twice with `plugin-publish` (commits `269e857` and `d7d3607` on main). ## What the user asked for and what the skill now says

- **Phase 4 Step 3 onward was rewritten to the Scan/Dispatch pattern of Phases 1-3.** Before, it was a mix of "Step 3 Scan / Step 2 Plan / Step 3 Dispatch / Step 4 Drift" with detailed split mechanics (`parents[N]` walks, numbered prefixes). The user's intent, verbatim: "refaktoriere alles wo docs über 400 loc haben in logische units". Now: Step 3 scans DOCS.md against 400 lines and determines logical units (entry point + modules only it imports; modules imported by two or more units stay in the root; orphan modules go to the user), Step 4 dispatches (one subfolder with own DOCS.md per unit, output directories stay in the root), Step 5 runs docs-drift-check. The user edited Step 3's wording himself ("separate Ordner ... logische Einheiten, welche sich in den separaten Ordnern widerspiegeln"); the three sub-bullets were then rephrased so each says where a module goes.
- **Established terms instead of German paraphrases.** User: "Wurzel root ist ein etablierter fachbegriff". Replaced: Wurzel -> Root, Einstiegsskript -> Entry Point, Ausgabeverzeichnisse -> Output-Verzeichnisse, Schwellenwert -> Threshold, Zweig -> Branch, Bericht -> Report. Kept on purpose: Verzeichnis, Kontrollfluss, Einheit (Unit would collide with unit test), Kontaktschicht (the user's own term).
- **Technical terms as guardrails.** Each phase got one or two lines naming the principle it follows (Fowler refactoring as behaviour-preserving transformation, Published Interface, SRP + Long Function/Large Module + Extract Function/Module, Self-documenting Code + ADR role of process-docs, FIRST + hermetic tests, Package by Feature + transitive closure in the import graph + High Cohesion/Low Coupling + Common Closure Principle, Documentation Drift, Fail Fast + YAGNI + Error Swallowing, four-eyes principle). The user then required a top rule: terms only give context and never justify deviating from a rule; on conflict the rule wins. That rule is the first rule of the skill.
- **Phase 5 runs without the user.** The earlier version had Main scan without classifying, a worker scan independently, and a merged list go to the user. User: "pahse 5 läuft ab jetzt komplett ohne user und nach dem selben prinzip wie 1 2 3 4". Now: Step 1 scan, Step 2 dispatch.
- **Phase 6 is the four-eyes principle, modelled on the doccheck skill.** A fresh worker activates the skill `iterative-dev:iterative-dev-refactor` (the user insisted on activation via the Skill tool, not "read the file"), runs only the scan steps of Phases 1-5, reports to Main; Main assesses each finding against the rules and dispatches the confirmed ones.
- Punctuation, spelling and grammar were corrected throughout; Phase 3's step numbering jumped from 1 to 3 and was fixed.

## Observed when the skill was run on four repos directly afterwards (2026-09-25)

- Phase 6 is not a formality. On gh-cli, rag-cli, reddit-cli and iterative-dev the four-eyes worker found real violations that five executed phases had left: orchestrators with logic, several orchestrators per module (rag-cli retriever had five), relative imports in all of rag-cli's `src/rag`, missing section markers in every shell module of iterative-dev, duplicated helpers across modules, wrong "Called by" entries in DOCS.md, dead modules. Roughly a third of each report was discarded by Main (shebang lines counted as comments, emojis in dev scripts, probes judged as tests, hypothetical conditions, dev copies of src logic).
- The Phase 1-5 scans as written only cover size, comments, test structure, DOCS.md format and fallbacks. They do not scan § Modulaufbau (section order, one orchestrator, no logic in the orchestrator, stepdown order, constants placement, absolute imports). Everything in that class surfaced only in Phase 6. Hypothesis: a Phase 2 step "scan against § Modulaufbau and § Import-Konvention" would move most Phase 6 findings earlier.
- Phase 0 was answered "no contact layer" for all four repos by Main without asking, because the user ordered a fully autonomous run.
- Phase 2 Step 2 says Main removes comments itself by script; the system prompt says all source changes go through workers. In this run workers executed the removal script. The skill text was not changed.
